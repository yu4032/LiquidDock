# Workspace 透明空帧清理（2026-10-11）

**基线：** `main` `1f9b29b`（已包含 Widget 背景恢复 PR #341）。状态：仅源码与 CI 验证，**尚未真机验证、不得直接合并**。

## 动机与证据

用户的多组件页面返回桌面 Perfetto 追踪显示：玻璃开启时存在 529 次静态输出交换，其中 100 次没有绘制任何玻璃节点（6 个连续区间）；玻璃关闭时 186 次均没有绘制节点。若这些区间内 EGL Surface 未更换，则理论上分别有最多 94、185 次重复透明交换可以避免。这只是可消除提交次数的上界，**不是实际帧率增益**。

同一追踪中，7 个 Widget 玻璃节点可见时，`StaticSwap` P90 约 9.81ms；空节点区间约 4.31ms。真正的多 Widget 掉帧问题仍需继续追踪 GPU/SurfaceFlinger；本优化只去掉空场景浪费。

## 保留的实现

`LauncherGlassEmptyOutputPolicy` 仅在 **当前静态 Surface 已成功呈现透明帧**，且当前快照没有可绘制玻璃节点时，允许略过重复的静态 `glClear` 和 `eglSwapBuffers`。

- 初次创建、重建、分离或调整尺寸后仍然正常绘制首次透明帧。
- 从有内容转成无内容，必须提交一次透明帧，避免留下旧玻璃。
- 节点重新出现后立即照常完整渲染。
- 不跳过 PassBlur 源帧、壁纸 freshness 回调或 Recents/Drag 更新。
- 不改变 Prismal 着色、采样分辨率、工作区/壁纸缩放与帧同步。

## 淘汰的方案

此前草稿 PR #342 曾尝试把几何驱动帧推迟最多一个刷新周期。按原始时间戳离线重放，约 169 次几何帧会被推迟，只有约 42 次可能被新的源帧合并。延迟导致动画跟手风险超过预期收益，**已彻底回退，不迁移到此干净分支**。

## 合并前真机检查

复现 App→HOME 与 Recents→HOME、桌面多 Widget 缩放/分页、玻璃反复启停、Widget 增删/淡出、SurfaceTexture 重新绑定、横竖屏。特别检查透明缓冲后 Widget 首帧是否立即恢复、有无残影以及壁纸比例错位。采集匹配操作的 FrameTimeline 对照 `StaticSwap`、`DrawnWidgets`，区分空场景节省和 7 Widget 可见时的持续卡顿。CI 通过不等于视觉验收。

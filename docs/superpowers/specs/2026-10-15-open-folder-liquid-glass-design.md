# 文件夹开合与展开态液态玻璃设计

日期：2026-10-15

状态：设计与计划已确认；已在专用本地分支实现，按反编译和回归测试修正接管流程，视觉验收待用户确认
基线：main `fda290670be85c3a119ccee87bf39ac22672c889`，已包含经真机确认的工作区透明度同步修复 #391。

## 已确认的目标

用户以 IMG_0890.PNG 为视觉参考，并确认如下效果：文件夹开合全过程保持液态玻璃，面板随动画扩展、收拢；展开后，面板保留玻璃折射与边缘高光，后方桌面模糊。

成功表现：从桌面文件夹玻璃开始，连续扩展成打开后的玻璃面板，关闭时连续收回。文件夹内部图标、文字清晰，后方仅显示模糊壁纸，工作区与 Dock 保留系统自身的 FolderState 视觉过渡，模块不额外隐藏它们来获取壁纸。布局采用当前系统文件夹的实际边界与内容布局，玻璃材质参照用户图片。

## 当前代码与原生行为

1. `MiuixFolderGlassHook` 目前主要替换 Workspace 内的 FolderIcon 背景。`dispatchFolderOpen` 将 Workspace 设为硬遮挡，并抑制桌面原文件夹节点。
2. 原生 `FolderCling.addFolderAnimIcon` 创建另一份动画文件夹副本。这份副本不在 Workspace 节点的玻璃覆盖范围内。
3. 原生 `FolderAnimController.setAnimIconBackground` 会生成或刷新动画副本的背景；`setIconBgAnim` 驱动其位移、缩放和淡出。部分路径还通过 `mCustomWidth`、`mCustomHeight` 和圆角改变背景尺寸。简单把原桌面玻璃保持可见，不能正确跟随这份动画副本。
4. 现有 ShortcutPopup 路径已经提供透明应用面板作为 PassBlur 采样权威、GPU 背景冻结、全屏稳定输出和动态玻璃几何，可作为复用基础。本次按用户最新要求改为仅采壁纸：独立采样源排除桌面根窗口及 DockAssistantView，复用已有窗口和渲染能力。

## 方案比较

| 方案 | 结果与取舍 |
| --- | --- |
| 只延后隐藏原文件夹玻璃 | 改动小，但玻璃仍停留在桌面原位置，无法覆盖动画副本和展开面板。 |
| 只给原生动画背景增加透明或模糊 | 跟随原生动画较容易，但无法提供与现有液态玻璃一致的折射和高光。 |
| 独立文件夹玻璃显示流程，复用已有 GPU 背景和材质能力 | 推荐。统一接管动画副本与展开面板的玻璃显示，保持原生内容与操作，同时明确背景采样和关闭恢复的归属。 |

## 2026-10-15 用户修订

- 背景仅模糊壁纸；工作区玻璃沿用多任务的缓存显示层加原生 Workspace alpha 路径，Dock 保留原生 FolderState 的淡出与恢复事务。
- 原生背景弹簧提供唯一进度；以同一个关闭态矩形和真实打开态面板矩形计算两方向几何，不在内容图标完成回调时切换矩形或强制完成背景弹簧。
- 中断打开后关闭，从当前玻璃进度收拢；关闭期间冻结打开态目标矩形，避免原生容器恢复布局使轨迹漂移。
- 无桌面 Surface 身份时保留原生，不将完整桌面当成壁纸输入。

## 推荐设计

### 1. 背景与玻璃分层

文件夹流程持有一份安全的桌面 GPU 背景，仅包含进入文件夹前的壁纸，并排除桌面根窗口及独立 Dock 窗口。准备优先从 ACTION_DOWN 开始，也允许与原生打开动画并行进行，可复用现有透明应用面板的采样机制。

进入打开态后冻结这份背景，不再从已显示文件夹的画面重新采样，避免把面板、文字和内部图标递归采入背景。壁纸或旋转改变时，旧背景失效；只在安全的桌面状态更新背景，不能把变尺寸的旧纹理拉伸显示。

显示分为两部分：后方桌面的模糊层，以及前方带折射、细描边和边缘高光的玻璃面板。内部图标、标题、输入框位于玻璃之上。背景模糊与玻璃光学分别控制，避免同时叠加原生和模块的两份模糊或压暗。

### 2. 原生动画作为唯一几何来源

开合期间读取动画副本背景的实际屏幕矩形、变换、有效自定义宽高和圆角；每帧投影玻璃几何到稳定的全屏输出。已经采样的背景始终固定在屏幕坐标，不能随整个输出纹理一起拉伸。

原生动画副本背景的淡出是原生材质交接的一部分，不能原样用作整块液态玻璃的透明度，否则仍会在打开过程中消失。玻璃的显示权由文件夹状态管理；几何跟随原生动画，整体透明度跟随当前文件夹显示状态。

打开完成后，几何来源交给原生 Folder 内容背景容器，玻璃覆盖图标网格的面板区域。关闭时从当前展开面板交回动画副本并连续收拢。交接必须使用上一帧有效矩形和新的同坐标矩形，避免尺寸或位置跳变。

### 3. 有条件地接管原生背景

新的玻璃首帧确认可显示后，才抑制对应原生面板及动画背景。保留原生 Drawable 的身份和动画需要的尺寸数据，只管理其绘制透明度或独立背景层，避免破坏原生强制类型转换、图标内容和布局计算。

背景准备不阻塞点击和原生动画；不 Hook Launcher.openFolder 进行等待。如果背景、输出或原生适配不可用，完整保留原生文件夹显示并释放模块资源。首帧准备能力必须在真机快速点击场景验证，不能只凭单元测试声称动画全程连续。

### 4. 状态与所有权

状态为：关闭 → 准备背景 → 打开中 → 已打开 → 关闭中 → 关闭。

- 单个 Launcher 根同时只有一个文件夹玻璃显示所有者。
- 打开、关闭、取消、快速换文件夹、无动画关闭、根脱离和配置关闭都必须有确定的回收路径。
- 所有异步捕获、GPU 输出和完成回调绑定当前打开序号，旧回调不得覆盖新文件夹。
- 原有 Workspace 文件夹遮挡仍负责桌面节点；打开态玻璃不受 Workspace 透明度影响，避免 #391 的同步因子误隐藏文件夹。
- 关闭完成或降级时恢复被管理的原生背景值，注销观察器并释放源与输出资源。

### 5. 配置与视觉

沿用现有全局玻璃参数及对应小/大文件夹功能开关。面板使用现有大表面高光配置，圆角依据原生打开态边界及尺寸限制，不按参考图硬编码像素。

本次不新增独立设置页面，也不修改原生图标网格、文件夹名称编辑、排序、拖出图标和点击行为。实现完成先交付本地签名测试包，待真机确认后再提交文件夹功能的独立 PR。

## 关闭动画和直接壁纸并行采样补充

1. `OPEN_FOLDER` 的 PassBlur 排除 Launcher 根 Surface 和 DockAssistantView；隔离的是 Source，而非 View 视觉状态，因此不需要临时隐藏 Dock、等待关闭 Dock 或恢复它才能采样。动态壁纸仍来自 SurfaceFlinger 后方合成。
2. 打开时直接交给原生 `Launcher.openFolder()`，删除预备纹理 `OpenFolderOpenGate`；若 EGL/壁纸首帧比动画慢，原生材质先正常显示，首个已呈现纹理出现后才由玻璃接管；失败只降级模块，不阻止原生操作。
3. 关闭使用同一固定的图标→展开面板端点、同一个 nativeVisualProgress（平移或 ScaleX），进度原生反转；中断开启动画关闭时上限取已经显示的当前帧，防止原生 setTo(expanded) 造成放大闪烁。
4. 在原生 Folder.onCloseAnimationFinished 生命周期释放资源；关闭中尚未呈现的晚到纹理不得突然切换材质。

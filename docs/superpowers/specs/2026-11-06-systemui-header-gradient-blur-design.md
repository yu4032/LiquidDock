# SystemUI 顶部渐变模糊开关

## 意图

为 LiquidDock 增加一个设置，让用户在设备支持 SystemUI 模糊、但厂商关闭顶部渐变模糊能力门控时，仍可启用控制中心和通知中心顶部的渐变模糊。

## 目标与边界

- 在“动画 → 系统界面”增加独立开关，默认关闭。
- 仅覆盖 SystemUI 顶部渐变模糊的厂商能力门控；保留 SystemUI 自身的模糊配置、省电及其他运行状态判断。
- 同时作用于控制中心和通知中心顶部。
- 不改普通面板背景模糊，不写系统属性，不增加 LiquidDock 自绘遮罩。
- 需要 LiquidDock 的 `com.android.systemui` 作用域；切换后重启 SystemUI 生效。

## 方案

1. **SystemUI 作用域 Hook（选定）**：在 SystemUI 进程中针对顶部渐变模糊门控做窄范围覆盖，设置值通过现有 API 102 Remote Preferences 提供。无需 root，且保留 MIUI 自身的模糊关闭状态。
2. **写入系统属性**：需 root/系统权限，属性在 SystemUI 初始化时读取，并可能影响该属性的其他消费者；不采用。
3. **LiquidDock 自绘顶部遮罩**：无法复用 SystemUI 的原生渐变模糊采样及生命周期，容易与系统面板重复绘制；不采用。

## 实施决定

- 使用现有 SystemUI 注入入口和配置同步方式，不增加权限、服务或新的进程通信。
- 设置变更通过 SystemUI 重启重新载入；控件说明明确标出作用范围与重启要求。
- 系统原有的 `miBlurOpen` 状态仍是启用前提，因此用户关闭系统模糊或进入系统强制禁用模糊状态时，LiquidDock 不会强行开启顶部模糊。

## 验收

- 设置项只影响 SystemUI 顶部渐变模糊门控，不更改全屏背景模糊设置。
- 开关关闭或 LiquidDock SystemUI Hook 未加载时，保持系统原生行为。
- 开关开启且系统模糊处于允许状态时，控制中心和通知中心顶部均走 SystemUI 原生渐变模糊路径。
